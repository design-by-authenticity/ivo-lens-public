# I·V·O I-POSITION PROTOCOL v0.2 — PRELIMINARY REGRESSION SUMMARY

Status: Frozen preliminary regression summary  
Protocol under test: I·V·O I-Position Test Protocol v0.2  
Canonical baseline: I·V·O Lens Prompt v4.1  
Cases: 4  
Purpose: Record the first cross-domain regression results before any further protocol revision.

---

# Core finding

**v0.2 produces position gain without selectivity inflation.**

Across the four tested cases, explicit I-positions regularly added analytically relevant information about access, visibility, exclusion, blind spots, and differences in appraisal.

No unsupported I-function was promoted to ESTABLISHED.

The primary analytical gain was therefore not “more I-functions,” but a clearer distinction between:

- **this position makes something visible**, and
- **this position performs a canonically established selective function**.

This distinction remained compatible with the v4.1 safeguards used in the tested cases.

---

# Regression set

The following four cases were rerun using canonical v4.1 with the experimental I-position protocol v0.2 as an additional execution layer:

1. Self-steering healthcare team
2. Double-slit / decoherence
3. Relationship pattern
4. Pre-Big-Bang cosmology

The protocol was not revised between cases.

# Position gain by case

## 1. Self-steering healthcare team

Position gain was clear.

The I-position layer made visible that different actors had materially different access to the same organisational structure.

Examples included:

- management access to performance indicators;
- departing experienced staff access to informal coordination problems;
- remaining staff access to ongoing daily workability;
- different visibility of direction, influence, coordination, and retention costs.

The gain was not a new causal explanation.

The gain was a more explicit reconstruction of **asymmetric access**.

### Main result

The team can appear operationally successful from one position while structural tensions remain visible from another.

### Main risk

Position proliferation remains possible if every organisational role is represented separately.

The remove-and-compare rule was therefore necessary.

---

## 2. Double-slit / decoherence

Position gain was smaller but methodologically useful.

The I-position layer helped distinguish:

- physical coupling;
- information-bearing relations;
- detector position;
- human observation.

The human observer was not retained because removing that position did not alter the experimental reconstruction.

The detector position was retained only insofar as it added analytically distinct information about accessible distinctions and registration.

### Main result

The analysis did not collapse:

- detector into selector;
- information into I;
- human observer into a necessary explanatory role.

### Main risk

This case showed the highest proliferation risk.

Without a strict safeguard, one could incorrectly multiply positions across:

- detector;
- detector subsystem;
- environment;
- memory register;
- measurement channel;
- human observer.

v0.2 therefore requires that information-bearing or physical coupling alone is insufficient for I-position.

---

## 3. Relationship pattern

Position gain was strong.

The two partner positions added information that was not captured as clearly by O/V alone.

The analysis could distinguish:

- behaviour;
- experienced meaning;
- inaccessible inner state;
- reciprocal escalation.

The protocol prevented the analysis from inventing unsupported motives such as:

- control;
- avoidance;
- indifference;
- dependency;
- hidden intent.

### Main result

The same behaviour can carry different meanings from different positions without requiring one position to be “the correct one.”

### Main risk

The main risk was inner-state inflation.

v0.2 reduced this by requiring explicit evidence discipline for access claims.

---

## 4. Pre-Big-Bang cosmology

Position gain was minimal.

The case was dominated by:

- O-reconstructions;
- model validity;
- theoretical extrapolation;
- epistemic limits;
- distinctions between unknown and undefined within model.

The protocol did not force an I-position where none was analytically necessary.

### Main result

Lack of position gain is a valid result.

The protocol should not require every analysis to contain I-position structure.

### Main risk

Low proliferation risk.

The main epistemic issue was distinguishing:

- UNRESOLVED;
- UNOBSERVED;
- INACCESSIBLE;
- UNDEFINED WITHIN MODEL.

# Strongest current interpretation

The principal value of v0.2 is not that it discovers more I-functions.

Its strongest contribution is that it separates:

**situated access and visibility**

from

**canonically evidenced selectivity**.

This allows the analysis to retain meaningful positional structure even where no I-function can be established.

In the tested cases this produced richer analysis without weakening the canonical v4.1 safeguards around I-function assignment.

---

# Current risk register

## Risk 1 — Position proliferation

Especially in physical and technical systems, many coupled or information-bearing subsystems could be incorrectly promoted to separate I-positions.

Current safeguard:

> Information-bearing alone is not sufficient for I-position.

> Physical coupling alone is not sufficient for I-position.

> A position must add analytical information beyond V.

---

## Risk 2 — Inner-state inflation

In social cases, position mapping can tempt the model to infer motives, emotions, needs, or beliefs.

Current safeguard:

Access claims must remain tied to supplied or supported evidence.

Observed behaviour does not automatically establish inner state.

---

## Risk 3 — O/V contamination

Position language can absorb structure that belongs under O or V.

Current safeguard:

- possibilities remain O;
- instantiated relations remain V;
- I-position represents position-dependent access, visibility, exclusion, registration, or appraisal only when analytically distinct.

---

## Risk 4 — Function overclaim

A useful position could be mistaken for an established I-function.

Current safeguard:

Position and function remain separate.

Function requires canonical v4.1 evidence conditions.

---

# Decision

**No further semantic or protocol revision is justified from these four cases alone.**

v0.2 should remain unchanged while the next test phase examines **positive-I cases**.

The next question is no longer only:

> Can v0.2 avoid inventing I-functions?

It must now also answer:

> Can v0.2 recognise a genuinely evidenced I-function without collapsing it back into O/V or leaving it permanently UNRESOLVED?

---

# Recommended next test phase

Use cases where a selective function should plausibly be establishable.

Candidate domains:

1. an algorithm selecting between multiple open options using explicit criteria;
2. a controlled human choice process with traceable selection evidence;
3. an organisation with a formal decision rule that demonstrably excludes alternative continuations;
4. a technical system with an independently traceable selective step distinct from simple coupling or threshold response.

The purpose of the next phase is to test for **false negatives** in I-function assignment.
