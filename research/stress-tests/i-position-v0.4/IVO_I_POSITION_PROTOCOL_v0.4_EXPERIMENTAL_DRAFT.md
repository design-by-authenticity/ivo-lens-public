# I·V·O I-POSITION / I-FUNCTION / I-AUTONOMY PROTOCOL

## Experimental Draft v0.4

**Status:** EXPERIMENTAL / NON-CANONICAL / TEST-ONLY  
**Canonical baseline:** I·V·O Lens v4.1 — Frozen Reference  
**Supersedes experimentally:** v0.3  
**Does not modify:** canonical v4.1  
**Purpose:** integrated experimental semantics after v0.3 regression  
**Decision basis:** v0.3 Regression Summary / Decision Note — PASS WITH OPEN POSITION BOUNDARY

---

# 1. Purpose

This protocol tests whether the I-dimension can be analysed more precisely by separating four questions that must not be collapsed into one another:

1. **I-position** — where a situated analytical difference exists;
2. **I-function** — whether a selective function is positively evidenced;
3. **Mechanistic implementation** — how that function is realised;
4. **I-autonomy** — whether structural openness remains after the strongest adequate O/V reconstruction.

The protocol is designed to preserve the canonical strengths of v4.1:

- unexplained ≠ I;
- missing knowledge does not establish I;
- O and V retain explanatory priority where sufficient;
- positive I-claims require evidence;
- all I-claims remain provisional and revocable.

At the same time, v0.4 addresses the positive-I false-negative identified during v0.2/v0.3 testing:

> A selective function must not disappear merely because its mechanism is well understood.

---

# 2. Canonical compatibility

This protocol is experimental.

It does not redefine canonical v4.1.

The canonical meanings remain:

- **O — Structured Possibility**
- **V — Instantiated Relation**
- **I — Situated Selectivity**

For this experimental protocol only, the I-domain is decomposed into separate analytical dimensions.

No experimental subcategory may be retroactively treated as canonical I.

No result from this protocol modifies v4.1 unless a separate governance decision explicitly does so.

---

# 3. Core experimental distinctions

## 3.1 I-position

An **I-position** is a situated configuration whose removal produces a non-redundant analytical loss that cannot be exhausted by ordinary O/V connectivity alone.

A positive I-position claim requires more than:

- physical location;
- receiving a signal;
- being connected to a source;
- having access to only part of a system;
- storing information;
- being an observer in ordinary language.

A candidate I-position must add analytically relevant structure concerning one or more of:

- access;
- distinction;
- visibility;
- exclusion;
- relevance;
- registration;
- persistence;
- situated viewpoint;
- scope-specific asymmetry.

The key test is not:

> Does this component have limited access?

but:

> Does the positional description add something analytically necessary beyond the complete O/V connectivity description?

---

## 3.2 I-function

An **I-function** is a positively evidenced selective function whose operation contributes to which continuation becomes realised within an explicitly declared analytical scope.

A positive I-function claim requires evidence that:

1. multiple relevant alternatives are available at the relevant stage;
2. those alternatives are functionally distinguished;
3. there is a selective consequence such as:
   - admission;
   - exclusion;
   - routing;
   - commitment;
   - prioritisation;
   - choice;
   - selection of a continuation;
4. the selective event/state is independently evidenced;
5. the selective result contributes to which relevant continuation becomes realised.

The selection may be:

- deterministic;
- stochastic;
- biological;
- technical;
- organisational;
- human;
- distributed.

None of these categories is sufficient by itself.

---

## 3.3 Mechanistic implementation

**Mechanistic implementation** describes how the evidenced function is realised.

Allowed statuses:

- **COMPLETE**
- **PARTIAL**
- **UNRESOLVED**

Mechanistic implementation is not itself an I-status.

A complete mechanism:

- does not establish I-function;
- does not revoke I-function;
- may support `I-autonomy NOT ESTABLISHED`.

An incomplete mechanism:

- does not establish I-function;
- does not establish I-autonomy;
- may leave I-autonomy unresolved.

Core rule:

> Mechanistic explanation neither establishes nor revokes I-function. It characterises implementation.

---

## 3.4 I-autonomy

**I-autonomy** concerns residual structural openness after the strongest adequate O/V reconstruction.

Question:

> After all relevant known O/V structure has been reconstructed, do multiple continuations remain structurally open at the relevant transition?

Allowed statuses:

- **ESTABLISHED**
- **SUPPORTED**
- **UNRESOLVED**
- **NOT ESTABLISHED**

I-autonomy must not be inferred from:

- missing knowledge;
- complexity;
- unpredictability;
- sensitivity to initial conditions;
- stochastic terminology alone;
- human involvement;
- unknown mechanism;
- multiple outcomes across different inputs.

Core rule:

> Unknown is not autonomy.

# 4. Independence rules

The four dimensions are analytically independent.

The following combinations are valid in principle:

### A
I-position ESTABLISHED  
I-function ESTABLISHED  
mechanistic implementation COMPLETE  
I-autonomy NOT ESTABLISHED

### B
I-position ESTABLISHED  
I-function ESTABLISHED  
mechanistic implementation PARTIAL  
I-autonomy UNRESOLVED

### C
I-position ESTABLISHED  
I-function NOT ESTABLISHED  
mechanistic implementation COMPLETE  
I-autonomy NOT ESTABLISHED

### D
I-position NOT ESTABLISHED / NOT REQUIRED  
I-function NOT ESTABLISHED  
mechanistic implementation COMPLETE  
I-autonomy NOT ESTABLISHED

### E
I-position NOT REQUIRED  
I-function NOT ESTABLISHED  
mechanistic implementation COMPLETE  
I-autonomy SUPPORTED

### F
I-position NOT REQUIRED  
I-function NOT ESTABLISHED  
mechanistic implementation COMPLETE  
I-autonomy UNRESOLVED

No status in one dimension automatically determines another.

# 5. Mandatory scope declaration

Every analysis must declare the relevant continuation before assigning I-function.

Required form:

**Primary analytical scope:**  
[what continuation is being explained?]

Examples:

- which energy source becomes active;
- which project is executed;
- which route is taken;
- which internal committee winner is registered;
- which physical branch becomes realised.

If multiple scopes exist, they must be separated.

Example:

- **S1:** internal committee decision
- **S2:** actual project execution

An I-function may be:

- ESTABLISHED for S1;
- NOT ESTABLISHED for S2.

This is not inconsistency.

It is scope dependence.

---

# 6. Scope-drift prohibition

A failed I-function claim may not be rescued by silently changing scope.

If the relevant continuation changes during analysis:

1. declare the new scope;
2. rerun the I-function test;
3. report both scopes separately.

Forbidden shortcut:

> “The committee did not affect execution, but it did affect its own recorded vote, therefore it was functionally selective for execution.”

That is invalid scope substitution.

---

# 7. Observation levels

Before O/V/I analysis, declare relevant levels.

Possible levels include:

- unit;
- component;
- subsystem;
- person;
- group;
- organisation;
- environment;
- system-of-systems.

Do not assume that a carrier valid at one level remains valid at another.

Do not infer:

- group mind;
- organism-level agency;
- system-level agency;
- person-level agency

unless independently supported.

---

# 8. O — Structured Possibility

Map the structured possibility space.

At minimum specify:

- relevant alternatives;
- constraints;
- admissible continuations;
- unavailable continuations;
- criterion space where applicable;
- probability structure where applicable;
- parameter dependence where applicable.

Distinguish:

- multiple possible states;
- multiple possible outputs across different inputs;
- multiple simultaneously relevant alternatives;
- structurally open continuations at one transition.

Do not infer I from multiplicity alone.

---

# 9. V — Instantiated Relations

Map instantiated relations.

At minimum identify:

- actual couplings;
- comparisons;
- mappings;
- transitions;
- measurements;
- rankings;
- registrations;
- commands;
- executions;
- interventions;
- realised outcomes.

Selection events may remain represented in V.

v0.4 does not require removing selection from V in order to recognise I-function.

Core rule:

> V may describe that a selection event occurred.  
> I-function classifies what that event functionally does.

---

# 10. I-position protocol

## 10.1 Candidate generation

Identify plausible position carriers.

Examples may include:

- person-in-task;
- committee-in-procedure;
- persistent register;
- observing subsystem;
- context-sensitive gate;
- distributed decision structure.

Do not automatically include:

- every sensor;
- every port;
- every memory location;
- every comparator;
- every network node.

---

## 10.2 Remove-and-compare

For each candidate ask:

> What analytically relevant information is lost if this position is removed?

Then ask the stronger v0.4 question:

> Is that loss already completely represented by ordinary O/V connectivity?

If yes:

> do not retain I-position.

If no:

> specify the non-redundant analytical gain.

---

## 10.3 Ordinary-connectivity challenge

A candidate position fails if it only restates:

source  
→ coupling  
→ signal

or:

node A  
→ link  
→ node B

or:

event  
→ sensor response

without additional analytical structure.

---

## 10.4 Positive position evidence

A position claim becomes stronger when one or more of the following survive the O/V challenge:

- persistent situated access;
- retained history that changes what is available from that position;
- context-dependent relevance;
- stable access/exclusion asymmetry;
- position-dependent distinctions;
- scope-specific information not recoverable from connectivity alone;
- different analytical consequences under relocation while ordinary connectivity description remains insufficient.

These are evidence candidates.

They are not automatic sufficient conditions.

---

## 10.5 I-position statuses

Use:

- **POSITION ESTABLISHED**
- **POSITION SUPPORTED**
- **POSITION UNRESOLVED**
- **POSITION NOT ESTABLISHED**
- **POSITION NOT REQUIRED**

Use `NOT REQUIRED` when O/V already provides a complete analysis and no independent positional layer is needed.

Use `NOT ESTABLISHED` when a candidate was tested but failed.

---

# 11. I-function protocol

## 11.1 Alternative availability

Ask:

> Are multiple relevant alternatives actually available at the selection stage?

Distinguish this from:

- different outputs across different inputs;
- hypothetical alternatives;
- table entries;
- physically impossible branches.

---

## 11.2 Functional distinction

Ask:

> Are alternatives functionally distinguished?

Evidence may include:

- scoring;
- comparison;
- evaluation;
- weighting;
- prioritisation;
- relevance assignment;
- admission/exclusion;
- routing;
- criterion-sensitive treatment.

But none is sufficient alone.

---

## 11.3 Selective consequence

Ask:

> Does the process produce a selective consequence?

Examples:

- one candidate is committed;
- some alternatives are excluded;
- one route is executed;
- one source is activated;
- only selected projects receive resources;
- routing differs based on evaluation.

Ranking without selective consequence is insufficient.

---

## 11.4 Independent selection evidence

Prefer evidence such as:

- pre-execution selection state;
- command register;
- winner state;
- decision log;
- independently stored choice;
- traceable transition from comparison to commitment.

A trace alone is still insufficient if it does not contribute to the relevant continuation.

---

## 11.5 Causal-contribution gate

This is mandatory in v0.4.

Ask:

> Does the selective state/event contribute to which continuation is actually realised within the declared scope?

Test using:

- intervention;
- counterfactual change;
- mediation;
- causal perturbation;
- stable association under held-constant alternatives.

If:

selection changes  
but realised continuation does not,

then I-function is not established for that continuation.

---

## 11.6 Intervention test

Where possible hold O/V background conditions stable and intervene on:

- weights;
- criteria;
- priority parameters;
- selection state;
- decision rule.

Ask whether the realised continuation changes.

Intervention on the physical environment alone is not evidence of a separate selective function.

---

## 11.7 I-function statuses

Use:

- **I-FUNCTION ESTABLISHED**
- **I-FUNCTION SUPPORTED**
- **I-FUNCTION UNRESOLVED**
- **I-FUNCTION NOT ESTABLISHED**

Do not use `NOT REQUIRED` for positive-I regression decisions in v0.4.

The question is whether the function is evidenced, not whether O/V can also describe it.

---

# 12. Mechanistic implementation protocol

Ask:

> How completely can the selective process be reconstructed?

## COMPLETE

All relevant steps are specified well enough that:

inputs + mechanism  
→ selective state  
→ continuation

is reconstructable.

## PARTIAL

Important steps are evidenced but the full mapping is not known.

## UNRESOLVED

The implementation cannot be reconstructed sufficiently.

Important:

> COMPLETE does not imply no I-function.

And:

> PARTIAL does not imply I-autonomy.

---

# 13. I-autonomy protocol

## 13.1 Strongest O/V reconstruction

Construct the strongest adequate O/V account first.

Include:

- all known constraints;
- states;
- probabilities;
- transition rules;
- mechanisms;
- parameters;
- histories where relevant.

---

## 13.2 Structural-openness question

Ask:

> After that reconstruction, do multiple continuations remain structurally open at the same relevant transition?

---

## 13.3 Distinguish four cases

### Case A — deterministic closure

Complete state + rule  
→ one continuation

Result:

**I-autonomy NOT ESTABLISHED**

### Case B — explicit stochastic openness

The model itself retains multiple continuations.

Result may be:

**I-autonomy SUPPORTED**

unless stronger evidence establishes more.

### Case C — unknown microdynamics

Multiple outcomes appear possible, but full state is unavailable.

Result:

**I-autonomy UNRESOLVED**

### Case D — independently evidenced residual openness

Multiple continuations remain open despite adequate reconstruction.

Result may be:

**I-autonomy ESTABLISHED**

This is a strong claim and requires strong evidence.

---

# 14. Mandatory distinctions

The following distinctions must remain explicit.

## 14.1 Mapping versus selection

input  
→ fixed output

is not selection by itself.

## 14.2 Thresholding versus selection

state + threshold  
→ unique output

is not selection by itself.

## 14.3 Ranking versus selection

comparison  
→ ordered set

is not selection unless the ranking contributes to a selective continuation.

## 14.4 Randomness versus selection

stochastic transition  
→ one realised outcome

is not I-function by itself.

## 14.5 Branching versus selection

physical bifurcation  
→ realised branch

is not I-function by itself.

## 14.6 Recording versus selection

event  
→ record

is not I-function by itself.

## 14.7 Access versus position

limited access  
≠ automatically I-position.

## 14.8 Winner state versus effective selection

winner recorded  
≠ I-function for a continuation

unless the winner contributes to that continuation.

# 15. Carrier rule

The **carrier** is the smallest system unit that realises the relevant positional or selective structure.

A carrier is not automatically:

- a person;
- an agent;
- an observer;
- a mind;
- an ontological entity.

Examples:

- controller decision module;
- committee-in-procedure;
- selection stage;
- persistent register.

Carrier choice must satisfy:

- minimality;
- stability;
- remove-and-compare;
- scope relevance.

---

# 16. Distributed selection

A selective function may be distributed.

Do not force selection into one individual component when the evidence supports a relational or procedural carrier.

Example:

committee members  
+ procedure  
+ scoring structure  
+ voting mechanism

may together realise:

`committee-in-procedure`

This does not imply group consciousness or group mind.

---

# 17. Nested selection

When a system contains multiple selection stages, analyse each separately.

Example:

candidates  
→ ranking  
→ shortlist  
→ veto  
→ final commitment  
→ execution

For every stage specify:

- alternatives;
- carrier;
- selective consequence;
- scope;
- downstream causal contribution.

Do not collapse all stages into one I-function unless the evidence supports that aggregation.

---

# 18. Partial causation

v0.4 explicitly recognises that a selection may contribute to continuation without being the sole cause.

For such cases ask:

> Does intervention on the selective process change the probability, route, timing, or identity of the realised continuation while other relevant factors are held stable?

Possible statuses:

- ESTABLISHED
- SUPPORTED
- UNRESOLVED
- NOT ESTABLISHED

Do not require sole causation.

Do require non-zero evidenced contribution.

---

# 19. Redundant selection

A system may contain multiple selectors capable of producing the same continuation.

Do not infer that a selector lacks function merely because another selector could compensate.

Test:

- intervention on selector A;
- intervention on selector B;
- joint intervention;
- realised continuation.

Distinguish:

- redundancy;
- epiphenomenality;
- overdetermination.

---

# 20. Position/function independence

A position may exist without function.

A function may require a position carrier, but the position claim must be justified independently.

Do not infer:

I-function ESTABLISHED  
→ I-position automatically ESTABLISHED

without a carrier analysis.

Likewise:

I-position ESTABLISHED  
→ I-function

is invalid.

---

# 21. Outside-view requirement

Every positive I-position analysis must include:

## Within reach

What is available from the position?

## Outside view

What is not available?

## Analytical relevance

Why does this distinction matter beyond ordinary connectivity?

If the final question cannot be answered, downgrade the I-position claim.

---

# 22. Revocation discipline

Every positive claim must include a revocation condition.

## I-position revocation

What finding would show that the position adds no non-redundant analytical value beyond O/V?

## I-function revocation

What finding would show that the apparent selection is merely:

- thresholding;
- mapping;
- ranking;
- recording;
- stochastic realisation;
- physical branching;
- epiphenomenal processing?

## I-autonomy revocation

What stronger reconstruction would close the apparently open continuation?

Positive I-claims without revocation conditions are incomplete.

---

# 23. Forbidden shortcuts

The following inferences are invalid.

### Position shortcuts

- sensor → I-position
- information access → I-position
- location → I-position
- memory → I-position
- observer label → I-position
- network centrality → I-position

### Function shortcuts

- alternatives exist → I-function
- threshold → I-function
- comparison → I-function
- ranking → I-function
- weighting → I-function
- winner state → I-function
- recording → I-function
- randomness → I-function
- branching → I-function
- human choice → I-function
- group vote → I-function

### Autonomy shortcuts

- unknown → autonomy
- unpredictable → autonomy
- stochastic vocabulary → autonomy
- complexity → autonomy
- incomplete mechanism → autonomy
- human involvement → autonomy

## FC-1 Selectivity inflation

Are human systems receiving easier positive I-status?

## FC-4 Position proliferation

## Step 9 — Failure checks

## Step 10 — Revocation conditions

State what would overturn each positive claim.

Report only what the evidence supports.

# 29. v0.4 success criteria

v0.4 succeeds only if:

1. genuine positive-I cases remain positive;
2. near-miss false positives remain excluded;
3. deterministic mechanism does not suppress I-function;
4. stochasticity does not create I-function automatically;
5. incomplete mechanism does not create autonomy;
6. ordinary connectivity does not create I-position;
7. epiphenomenal selection is excluded at the relevant scope;
8. partial causation can be represented without requiring sole causation;
9. redundant selectors can be distinguished from irrelevant selectors;
10. nested selections remain scope-stable;
11. carrier choice remains reproducible;
12. O and V remain intact.

---

# 30. v0.4 failure criteria

v0.4 fails if it systematically produces any of the following:

- thermostat = I-function merely because it switches;
- lookup = I-function merely because it maps;
- RNG = I-function merely because one outcome occurs;
- bifurcation = I-function merely because one branch realises;
- sorting = I-function merely because alternatives are ranked;
- sensor = I-position merely because it receives a signal;
- register = I-function merely because it stores information;
- committee = I-function for execution when its decision has no effect;
- deterministic algorithm loses I-function because its mechanism is complete;
- human case gains autonomy merely because mechanism is incomplete;
- carriers change opportunistically to preserve preferred results.

# 33. Minimal experimental semantics

The smallest form of v0.4 is:

### I-position

> A situated configuration whose removal causes non-redundant analytical loss not exhausted by ordinary O/V connectivity.

### I-function

> A positively evidenced selective function that contributes to which continuation becomes realised within an explicitly declared analytical scope.

### Mechanistic implementation

> The reconstruction of how that function is realised; completeness neither establishes nor revokes the function.

### I-autonomy

> Residual structural openness after the strongest adequate O/V reconstruction.

These definitions must be interpreted together with the safeguards in this protocol.

---

# 34. Final experimental statement

v0.4 adopts the following working separation:

> **Position asks from where or within what situated configuration a relevant difference exists.**

> **Function asks whether a selective process actually contributes to which continuation is realised.**

> **Mechanism asks how that function is implemented.**

> **Autonomy asks whether more than one continuation remains structurally open after the mechanism is adequately reconstructed.**

The experimental purpose is not to maximise the number of I-assignments.

It is to minimise both:

- false-positive I inflation;
- false-negative suppression of evidenced selective functions.

The governing discipline remains:

> **Unexplained is not I.**

and, additionally:

> **Explained is not therefore non-I.**
